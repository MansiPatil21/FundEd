# Deploying FundEd

The web app runs on **Vercel**. The API, the optimizer and Redis run on **Render**, described by
[`render.yaml`](../render.yaml). MongoDB runs on **MongoDB Atlas**, because Render does not host
MongoDB. Everything below fits in the free tier of all three.

```
Browser ──> Vercel (Next.js, web/)
   │
   └──────> Render funded-api (Express, GraphQL, Socket.IO) ──> MongoDB Atlas
                  │                                      └──> Render funded-redis (cache, poll schedule)
                  └──> Render funded-optimizer (FastAPI, OR-Tools), over its public URL
```

The two sides need each other's address: the web app is built with the API's URL, and the API
only accepts browser requests from the web app's URL. So the order is Atlas, then Render, then
Vercel, then one setting back on Render.

## 1. MongoDB Atlas

1. Create a free **M0** cluster. Choose **AWS, Oregon (us-west-2)**, the same region as Render's
   `oregon`, so every query does not cross the continent.
2. **Database Access**: add a database user with a generated password. Letters and digits only
   saves URL-encoding it later.
3. **Network Access**: add `0.0.0.0/0`. Render's free services have no fixed outbound address,
   so there is nothing narrower to allow. The database user and password are the protection.
4. **Connect > Drivers**: copy the connection string and add the database name `funded` before
   the `?`:

   ```
   mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/funded?retryWrites=true&w=majority
   ```

Atlas clusters are replica sets, which Prisma requires for MongoDB, so nothing else is needed.
The API creates its indexes itself on every start.

## 2. Render

1. **New > Blueprint**, connect GitHub, and pick the `FundEd` repository. Render reads
   `render.yaml` and proposes three resources: `funded-api`, `funded-optimizer` and `funded-redis`.
2. Fill in the three values it asks for:

   | Variable | Value |
   | --- | --- |
   | `DATABASE_URL` | The Atlas string from step 1 |
   | `OPTIMIZER_URL` | `https://funded-optimizer.onrender.com` |
   | `CORS_ORIGIN` | `https://funded.vercel.app` for now; corrected in step 4 |

   `JWT_SECRET` and `FX_WEBHOOK_SECRET` are generated by Render and never need to be seen.
3. **Apply** and wait for both builds. The optimizer image is the slower one.
4. Check the service URLs Render assigned. If a name was taken, Render adds a suffix
   (`funded-optimizer-ab12.onrender.com`). If so, set `OPTIMIZER_URL` on `funded-api` to the real
   optimizer URL under **Environment**.
5. Open `https://<api-url>/health`. Expect:

   ```json
   {"status":"ok","services":{"mongo":"up","redis":"up","optimiser":"up"}}
   ```

   A `503` with `"optimiser":"down"` just after deploying usually means the optimizer is still
   waking up; reload after a minute.

## 3. Vercel

1. **Add New > Project**, import the `FundEd` repository.
2. Set **Root Directory** to `web`. Vercel detects Next.js; leave the build settings alone.
3. Add one environment variable, for Production and Preview:

   | Variable | Value |
   | --- | --- |
   | `NEXT_PUBLIC_API_BASE` | The API URL from Render, such as `https://funded-api.onrender.com`, with no trailing slash |

4. **Deploy**, then note the production URL Vercel assigns.

`NEXT_PUBLIC_` variables are compiled into the site at build time. If the API URL ever changes,
update it here and **redeploy**; saving the variable alone changes nothing on the live site.

## 4. Back to Render: allow the web app

On `funded-api`, **Environment**, set `CORS_ORIGIN` to the exact Vercel production URL, with
`https://` and no trailing slash, then save. Render redeploys the API.

To let Vercel preview deployments reach the API too, list both, comma-separated:
`https://funded.vercel.app,https://funded-git-main-yourname.vercel.app`.

## 5. Check it end to end

1. Open the Vercel URL. The first request after a quiet spell can take about a minute while the
   free Render services wake.
2. Create an account, finish setup, and reach the dashboard greeting.
3. Set a rate alert. The current CAD/INR rate appears once the poller has run, which it does on
   every API start.
4. Open **Plan transfers**. A `503` naming the optimizer means it is still waking; try again.

## What the free tier means in practice

- **Cold starts.** Render stops a free web service after 15 minutes without traffic and takes
  about a minute to start it again. Each service sleeps independently.
- **Rate polling pauses while the API sleeps.** The poller runs on every start and then every six
  hours while awake, so an alert fires on the next poll after the API wakes, not at the moment the
  rate moves.
- **Redis is not persistent.** The free Key Value instance loses its data on restart. It holds only
  the rate cache and the poll schedule, both rebuilt on start; accounts and alerts live in MongoDB.
- **750 free instance hours a month** are shared across the workspace's services. Sleeping
  services use none.
- **Sign-in attempt limits reset when the API restarts**, since they are held in memory.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| Browser console shows a CORS error | `CORS_ORIGIN` does not exactly match the Vercel URL (scheme, no trailing slash) |
| "Could not connect to FundEd" on every page | `NEXT_PUBLIC_API_BASE` is wrong or was changed without redeploying Vercel |
| API logs show `Authentication failed` from Prisma | Atlas user or password wrong, or the password needs URL-encoding |
| API logs show a server selection timeout | `0.0.0.0/0` missing from Atlas Network Access |
| Live rate alerts never arrive but the dashboard works | A proxy or extension blocking WebSockets; the dashboard still refreshes on load |
